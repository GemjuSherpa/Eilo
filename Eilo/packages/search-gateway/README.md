# Offline search boundary

This server-only Node workspace is disconnected from the shipping mobile app. It has no HTTP listener, provider SDK, fetch/DNS call, account, key enrollment, deployed gateway or approved provider profile. Default construction cannot issue a preview or ticket. Fixture approvals and generated test keys are not production permission. No external dependency was added.

The confirmation core bounds exact query bytes and pending records, admits text only, and requires a registered P-256 public key to verify a one-use challenge bound to provider and query hash. Tickets expire on a monotonic clock and are consumed once even after an invalid request. Scope cancellation/clear releases pending references; diagnostics expose counts only. It never reads history, location, audio or an account identifier and writes nothing to storage/logs.

A signature proves possession of a registered key, **not that a user saw or confirmed a query**. Activation requires a separately implemented trusted native view/voice confirmation adapter that presents the exact query/provider, checks active/unlocked session and explicit consent, then signs only that challenge. Key registration must be approved/authenticated outside the request body. Neither native adapter nor registration exists. The caller's opaque scope must be server-bound; accepting an arbitrary client scope or public key would defeat the boundary. No app route/permission is enabled by this package.

Unknown provider rights, retention, region, funding, confirmation registration or transport keep live search disabled. Query minimization is not proven by a JSON schema; a reviewed native caller must supply only the user-approved minimized query. These tests verify offline protocol properties, not physical packet privacy, native user consent or legal/provider approval. Releasing strings is not certified memory erasure.

The gateway core consumes the ticket before policy/budget/network checks, rejects extra payload fields and non-text media, and passes only query/text plus an AbortSignal to an injected fixture transport. It bounds request/response bytes, per-instance attempts, concurrent outstanding transports and deadlines. An abort-ignoring transport occupies its slot until it settles; revoked/late results cannot publish. No raw provider error is returned. The budget callback must synchronously reserve an exclusive externally funded slot; missing, false, throwing or async results deny. The in-memory attempt counter is not a global billing ledger and cannot establish funding across restarts/replicas. No real reservation adapter is configured.

Transport/header/TLS/authentication/streaming bounds and access-log suppression are deployment work, not demonstrated by an in-memory request function. A real transport must enforce its byte/decompression limits while reading, honor cancellation, use only approved endpoints and not follow redirects. The core's post-read byte check cannot prevent an unbounded adapter from allocating a large response. No such network adapter or listener is included.

The built-in result normalizer cannot be replaced by a request/adapter-supplied callback. It accepts only bounded JSON with explicit sources, canonical optional dates/license references and bounded plain-text details. Extra fields, markup, tracking queries/fragments, non-HTTPS URLs, credentials/ports, literal IPs and private-name suffixes reject the response. This is attribution syntax validation, not DNS/SSRF resolution or proof that a publisher's facts/license claim is correct. Normalized records remain `sourceVerified: false`; both media flags are unavailable. Output is deeply frozen and contains no executable action. Native projection into the S14 card schema is not yet connected; the internal evidence metadata is not an implicit app envelope.
