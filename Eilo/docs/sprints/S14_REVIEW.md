# S14 — visual conversation implementation

S14 proceeds independently of the outstanding S08 physical feasibility decision. Storage, recall and persistent memory remain disabled/dependency-blocked. Task branches consolidate into one final sprint PR after all available independent work is verified.

## VC-VIS-01 — controller-driven ripple

Home now renders blue/lavender rounded decoration from the existing native metadata snapshot. Only listening and speaking animate; thinking, standby, stopped, pending capture and unavailable/error states remain distinct through shape and the existing live state label. The decoration is hidden from accessibility traversal; Start/Stop remains separate and accessible. It starts no capture, inference or playback. Stop and state replacement reset the animation; background and reduced motion freeze it. Unknown motion preference defaults to static, and a late preference query cannot override a newer accessibility event.

Validation: 21 mobile tests, TypeScript and ESLint pass; every controller state, pending capture, error, Stop, background, reduced motion and a stale accessibility query are covered. 309 Swift tests, normal simulator build/install and three fresh ten-second launches pass (s14-ripple). These are implementation/regression results, not physical visual, VoiceOver or TalkBack acceptance.

VC-VIS-03 needs a separate bounded volatile spoken-content channel: the existing state contract intentionally forbids text and must retain that boundary. Full joined native speech, physical visual/accessibility acceptance and unsupported background operation are not inferred from this change.

## VC-VIS-04 — independent display preferences

Native version-2 consent metadata adds text (on), images/video (off) and Voice only (off) defaults. Legacy version-1 choices migrate without changing history, background consent or volume. Individual choices persist when Voice only is toggled; its effective presentation is disabled without erasing them. Foreground/unlocked host guards and the native allowlist protect preference changes, and failed saves do not publish a changed choice. No voice-command route is exposed: an unbound/unknown voice preference request is denied; future voice interpretation still requires an active authorized native session and separate validation.

Settings sends only the four bounded native preference commands; it starts no media request, playback, microphone or history feature. The state-event schema remains metadata-only. The preference decoder accepts only version 2 with the exact Boolean display fields and rejects added content. Home hides conversation decoration in Voice only while keeping safety controls available.

Physical settings/voice-command acceptance remains unrun; no physical gate is promoted.

## VC-VIS-03 — completed spoken-clause fallback

The native clause queue publishes text only after its SDK-completed callback. Draft fragments, waiting clauses and an unfinished cancelled clause never enter the presentation channel. Separate volatile controller storage is opt-in from the foreground/unlocked host and text preference, bounded to 32 clauses/4096 UTF-8 bytes, and marks omitted earlier clauses. The normal end-of-reply transition preserves completed text; a new query, Stop, lock/privacy transition, failure or disabling the presentation policy clears it. Explicit replacement and SDK interruption show a generic interruption label without publishing unfinished text. This does not prove acoustic completion or that a person heard the words.

`presentation` is a separate read/envelope through the existing native command transport; it is not part of the content-free state event or telemetry. The host checks foreground/unlocked access and the native preference; the controller also checks current permission, model and privacy state. JavaScript accepts only closed, bounded fields matching the current session/operation/generation/privacy epoch. The Home reader stops when hidden, busy, disabled or backgrounded, and rejects late responses. Text is plain native Text, with no URL action, external request, clipboard write or persistence. Ordinary shipping voice remains unavailable until the joined native caller/runtime is configured; no simulated clause is injected into the production UI.

Before exposing content, iOS now places a native cover on resign-active and keeps it until a current stopped-identity acknowledgement follows a cleared React view. A stale acknowledgement cannot reveal a newer session. Android sets its secure-window flag before content creation and disables/clears presentation on pause even if an authorized generic service continues. These are implementation mechanisms; physical app-switcher/recording/privacy and assistive-technology acceptance remain NOT_RUN. Releasing String references is not certified memory erasure.

Validation: 32 mobile tests, TypeScript/ESLint; 317 Swift tests; 370 Android native tests (offline); final normal simulator build/install and three fresh ten-second launches (s14-spoken-final). Focused tests cover completed versus unfinished clauses, normal turn completion versus new-query clearing, opt-in/disabled recording, Stop/lock, late callbacks, bounded retention, interruption labels, plain rendering, stale generations and background in-flight reads. The original personal checkout diff remains unchanged.

## VC-VIS-06 — bounded visual inactivity

A monotonic twenty-second inactivity policy hides the current visual card only while speech, processing, loading, video, pinning and keyboard focus are inactive. Touch, scroll, source revisions and activity transitions reset the deadline; synchronous event timestamps close the timer/event race. Unknown screen-reader/clock state conservatively retains the card, and screen-reader use disables automatic hiding. Hiding neither stops nor starts native audio. Hidden identities stay hidden across revisions; a different native card identity can appear. Native card IDs remain stable across ordinary reply completion and change on a new query.

Validation: 48 mobile tests, TypeScript and warning-free ESLint; 318 Swift tests; offline Android suite; normal simulator build/install and three fresh ten-second launches (s14-inactivity). Focused tests cover the exact deadline, every activity blocker, touch/deadline races, revision resets, accessibility-query races, focus, new cards and stale hide closures. Provider loading and video remain unconfigured; their policy inputs are tested without claiming integrated source/player acceptance. Native volatile reference clearing on dismissal follows in VC-VIS-07; this step only hides the view. Physical interaction/accessibility acceptance remains NOT_RUN.

## VC-VIS-07 — pin, dismiss and stale-card rejection

Pinning applies only to the current session/card and survives the normal end-of-reply generation change; a new card is unpinned. Dismiss remains available while pinned. Manual dismissal drops the JavaScript clause reference immediately and requests native visual-only clearing; it does not stop speech/listening. Native dismissal compares session/privacy epoch/card nonce under the controller lock, suppresses further clauses for that reply (including across presentation-policy toggles), and resets for a new query. A stale command cannot clear a newer reply. Native automatic dismissal additionally requires standby/error; unknown/rejected acknowledgements keep the visual card visible. Native errors are handled locally rather than entering Android's stop-on-invalid-control path.

Validation: 51 mobile tests, TypeScript and warning-free ESLint; 320 Swift tests; 373 offline Android tests; normal simulator build/install and three fresh ten-second launches (s14-pin-dismiss-final). Tests cover pin/idle/end-of-reply, dismiss while pinned without audio commands, stale native/JS callbacks, suppression through normal completion and policy toggles, new-query replacement and rejected/stale auto-hide acknowledgements. Released String references are not certified erasure. Actual source-request cancellation remains blocked on the unconfigured S15 result broker; no production result request exists to cancel. Physical pin/lock/assistive-technology acceptance remains NOT_RUN.

## VC-VIS-08 — media boundary; live playback BLOCKED

The independent denial path is implemented: images/video default off, Voice only suppresses them, source metadata cannot authorize media, and unavailable video retains the completed spoken-answer route. There is no autoplay, URL-opening action, raw URL image view, player package, or production media request. Existing ResultCards tests verify both media preferences enabled still render unavailable text and create no Image or URL action. This is a denial-path result, not a successful playback trial.

Actual tap-to-play is BLOCKED on S15's assessed/authorized source and a native asset broker. Before activation, the broker must authorize a bounded asset handle tied to the current query/session/privacy epoch, recheck rights/type/size, and reject stale/dismissed work. A native player must wait for acknowledged speech and capture shutdown before accepting the handle; completion, failure, interruption and dismissal must release it and keep conversation paused until an explicit Resume conversation action. No remote URL may bypass this broker through React Native Image, WebView, Linking or an external player. No new dependency, provider/account, download, or microphone/speaker trial is needed or authorized by this review.

Pending validation: approved asset rights/provenance, stop-acknowledgement failure, interrupted playback, network/decoding failure, current-card cancellation, completion and explicit resume on both platforms; physical proof that video audio never feeds ASR remains NOT_RUN. Until these dependencies are supplied and tested, the live-playback task stays BLOCKED rather than COMPLETE.
