# iPhone network-observation supporting sprint

Status: planning/tooling only; no network trace has been recorded. Independent network observation and full VC-LLM-06 acceptance remain NOT_RUN. S08 remains HOLD and persistent memory remains disabled.

The next collection uses the installed, signed Eilo Foreground Trial and the approved fixed generic model inputs. No new app, package, model, service or microphone/speaker access is required. Apple Instruments provides a Network template with Network Connections and HTTP Traffic instruments. Its HTTP instrumentation can include decrypted application HTTP content and related system metadata. Explicit operator permission is required before recording; the tool listing and recording-options inspection performed so far did not start a recording.

`packages/physical-ios-trial/network_trace.py` only prints a recording plan. Supply the actual connected device UDID and a freshly verified Eilo process ID; neither a stale PID nor a process-name guess establishes identity. The command targets that PID, uses a new local trace path and bounds duration to 30–1200 seconds. It never invokes a recorder, records all processes, suppresses native privacy prompts, launches an app or exports HAR. Existing traces cannot be overwritten by the plan. The trace remains local; review/commit only redacted numeric counts and provenance, not payloads, URLs, credentials or raw trace data.

After permission, verify the installed signed binary against the existing resident-build provenance and obtain the live lab-app PID. Start a fresh fixed no-audio run under the existing trial authorization, attach the external observer, record actual start/end and sample coverage, and preserve the app's numeric aggregate before another run. A bounded trace may cover only part of the 36-sample comparison; report that exact scope rather than assigning coverage to the earlier run or every candidate/condition. Trace attachment failure, missing target/process coverage, dropped data or unsupported tables must remain explicit blockers. Empty tables alone cannot prove absence of all traffic. Apple HTTP-stack observation is not automatically complete visibility of every transport or delegated process. No full no-traffic acceptance is inferred without verified observer coverage.

Tooling checks reject invalid target IDs/PIDs, booleans masquerading as numbers, unbounded durations, relative paths and existing trace paths. Normal/optimized test commands are wired into synthetic CI. Existing iPhone evidence and gate metrics remain untouched in this task.

References: [Apple: Analyzing HTTP traffic with Instruments](https://developer.apple.com/documentation/foundation/analyzing-http-traffic-with-instruments), [Apple WWDC21: Analyze HTTP traffic in Instruments](https://developer.apple.com/videos/play/wwdc2021/10212/). Installed `xctrace help record` documents explicit PID attachment, time limits and privacy-prompt controls.
