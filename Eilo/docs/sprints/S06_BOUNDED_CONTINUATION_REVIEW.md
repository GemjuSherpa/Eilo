# S06 / VC-LLM-05 review

A native continuation policy now requires an explicit longer-reply request and current native authorization. The controller permits one policy per generation, so creating another policy cannot reset its bound. It accepts at most four chunks of 1–256 generated tokens each, at most 1024 total. Each chunk uses a fresh loaded-model tokenizer and the 4096-token prompt builder. Older context is trimmed deterministically; fixed rules, the original request and the previous approved chunk must remain available, or continuation fails closed.

Each completion must match the exact pending chunk object, carry explicit native policy approval and bounded non-thinking text/count. Default request, authorization and approval gates deny continuation. Acceptance does not automatically request another generation. Stop publishes a short cancellation signal before replacing the token, without counting or joining under the controller. Worker returns clear borrowed references; String/vendor erasure is unverified. No ordinary app generation loop or speech authorization is enabled; S07 will join these capabilities.

Validation: five focused tests per platform cover a fake 1024-token stream across four bounded chunks, exact prompt budgets, default gates, approval denial, oversized/duplicate/stale completions, cancellation during token counting, irreducible context and one-policy/Stop enforcement. Strict Swift source compilation and Android lint pass. Same iPhone simulator app build and three fresh ten-second launches pass before commit. Final sprint checks cover native controller regressions and runtime links.
