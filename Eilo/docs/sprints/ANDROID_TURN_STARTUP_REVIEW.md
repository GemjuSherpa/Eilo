# Android native reply startup and request lifetime

Base main `7eadd34f54eac078858313f1be79c93b3fa4b2ef`. This is an implementation follow-up to VC-JOIN-01/04, not a new planned sprint or a full joined-runtime acceptance claim.

A generation adapter throwing from `start` previously escaped GenericSpokenTurn.submit and left the native controller in thinking. An adapter rejecting startup could retain the GenericReplyRequest's input/history references. Two new tests reproduced these failures before the fix (exception escape and retained-text comparison failure).

GenericSpokenTurn now owns the pending request through startup. Exception/rejection clears it and follows the existing generic unavailable failure/cancellation path without logging adapter details. Queue revocation clears it on Stop/privacy cancellation even before an adapter's completion. Normal completion also clears it; successful approved clauses still finish normally. A Stop followed by a starter exception stays stopped, and late callbacks after rejection cannot speak or resume work. Clearing owned references is not certified erasure of immutable strings or copies made by an adapter. Fatal VM Errors are not caught as ordinary startup exceptions.

Five new regressions cover throwing startup, rejected startup with late output/completion, Stop before completion, normal completion, and Stop followed by exception. Full normal Android suite: 378 tests, zero failures/errors/skips. Offline Android lint, Debug assembly and Release Kotlin compilation pass. Workspace lint/types and 58 mobile/33 contract/27 search tests pass; 320 Swift tests and the normal simulator build/install/three fresh ten-second launches pass (android-turn-startup-safety).

Because signed-installer evidence pins this Android source, both actual eight-case signed VAD/ASR installer checks were rerun: macOS JVM/JNI and iOS simulator pass using approved cached models/runtimes. No download, microphone, Android ART/physical test or production trust/readiness change occurred. Their aggregate reports and evaluated-source pins were refreshed from those runs; unchanged iOS report bytes remain unchanged. Four installer evidence regressions pass in normal/optimized Python.
