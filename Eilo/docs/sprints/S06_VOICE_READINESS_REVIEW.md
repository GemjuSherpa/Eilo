# S06 / VC-VOICE-01 — offline voice readiness

Native Kotlin/Swift registries now select only installed English voices with a network-independent flag or explicit offline evidence when capability is unknown. Missing, network-only, uninstalled, unknown, duplicate and oversized snapshots fail closed. Explicit requested voice IDs never fall back to another voice. Refresh/invalidation revokes old selection epochs. A composite native readiness adapter returns `offline_voice_missing` only after the model readiness prerequisite is ready. The ordinary app retains its missing-model default.

Compiler/lint and four focused Kotlin plus four focused Swift tests PASS; same iPhone 18 Pro normal Debug build and three fresh ten-second launches PASS before commit. Unknown capability does not become verified from voice quality or simulator availability. Platform adapter/physical offline checks follow in VC-VOICE-02/03/06. New Swift source references are scoped; personal signing/plist/S02 edits remain excluded.

The [Android Voice API](https://developer.android.com/reference/android/speech/tts/Voice) exposes its network requirement. [Apple's voice registry](https://developer.apple.com/documentation/avfaudio/avspeechsynthesisvoice/speechvoices%28%29) describes language/voice selection without a comparable network-independence field; iOS therefore requires explicit per-voice/OS offline evidence. Registry fixtures use synthetic evidence and do not certify installed platform voices.
