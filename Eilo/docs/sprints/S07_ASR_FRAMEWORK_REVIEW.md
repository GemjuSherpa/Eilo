# S07 iOS ASR framework packaging and relocation

The earlier joined iOS evaluator isolated the Moonshine archive behind four C exports in a loose dylib. This task turns that reviewed boundary into an actual local XCFramework with ARM64 device and simulator framework slices. It does not attach the runtime to the normal app or grant production readiness.

`packages/asr-runtime/framework.py` verifies the approved Moonshine v0.1.5 archive, extracted libraries/headers and model bytes before building, then rechecks them after execution. It compiles the unchanged Eilo ASR shim for iOS 18.0 device/simulator, links the unchanged vendor archive using TWOLEVEL namespace and the exact four Eilo C exports, sets `@rpath/CEiloAsr.framework/CEiloAsr`, and packages the existing C header/module for Swift import. No vendor patch or duplicate-symbol suppression is used. Xcode creates the XCFramework and every copied slice is re-inspected for architecture, platform/minimum OS, install name, exports, permitted dependencies, metadata/header/module bytes and signing class. No x86_64 simulator support is claimed.

## Actual execution

Both full framework links passed, including the device vendor archive (not just a wrapper compile). Actual binary sizes: device 24,552,752 bytes; simulator 24,545,800 bytes. The device binary is unsigned; the simulator binary has a toolchain ad-hoc signature. No developer certificate, provisioning profile or signing command was used. This is not developer-signed device execution, distribution approval or a legal/notice completeness determination.

An independent, fresh CPU-only LLM static build uses the existing checksum-pinned llama.cpp archive and verified unmodified source tree with the previously reviewed build options. A standalone Swift client imports the framework module and current native streaming ASR adapter, links the actual Eilo/LLM libraries, and keeps the LLM unloaded/canceled. It copies the simulator framework from the finished XCFramework into its own Frameworks directory, uses only `@executable_path/Frameworks` for that dependency, then moves the client directory. The runtime search-path guard permits exactly the system Swift path and `@executable_path/Frameworks`, rejecting absolute build-directory fallbacks. The original client directory is absent when the existing iOS 27 ARM64 simulator executes it.

The relocated client produced one final from the existing frozen synthetic question fixture, rejected a duplicate final, and rejected a stale final after Stop. The real linked LLM rejected tokenizer access while unloaded/canceled. No LLM model was loaded and no reply generation or speech SDK was executed. Synthetic evaluator readiness/permission and an explicitly verified local model are used only inside this file-fed client; they do not configure production pack trust. No microphone, physical phone, app installation, model/source/package download, service or account was used.

An initial relocation inspector incorrectly included otool's printed input filename in its dependency-path check. Corrected dependency-entry inspection was followed by a fresh full build and successful execution; no failed build was relabeled or blindly repinned. Failed invocation logs remain local; only the final aggregate observations are committed. No audio, transcript, model, native binary, signing identity or private cache path is uploaded.

## Validation and limits

Eleven ASR package tests pass in normal and optimized Python with no skips (nine framework regressions plus two existing quality-report tests). They cover wrong exports/platform/architecture/namespace/install name, unexpected dependency paths, XCFramework traversal/duplicate slices, changed headers/modules/metadata, symlinks, stale source hashes, signing/device/generation/release promotion, and export/no-overwrite behavior. CI validates the recorded aggregate report without native caches or models, exporting only JSON/HTML summaries for seven days. Exact-head hosted checks remain required before merge.

The local XCFramework and relocated client are retained in ignored `.local/asr-framework/build-v4`; no binaries are committed. Earlier generated builds remain separate. The host simulator was already booted and is left in its existing state; the personal checkout is unchanged. This closes a concrete packaging/relocation subtask, not production framework embedding or S07/S08 acceptance. Actual developer signing, normal app embed/caller, production pack trust/licensing, model readiness, physical device execution, confidence quality, latency, network and end-to-end voice gates remain open. S08/release HOLD and persistent memory DISABLED remain unchanged.
