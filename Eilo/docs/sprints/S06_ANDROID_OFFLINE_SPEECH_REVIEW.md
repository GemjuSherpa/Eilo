# S06 / VC-VOICE-02 — Android offline speech adapter

The native adapter uses an exact installed English `Voice` with `isNetworkConnectionRequired == false` and no not-installed feature; it never calls setLanguage, substitutes a network voice, opens a download prompt, writes synthesized files or returns raw text in callbacks. SDK work/events run on an exclusively owned serial worker. Requests bind a controller generation token and voice-selection epoch, keep at most one clause, clear queued references on cancellation, reject late callbacks and schedule stop/shutdown outside controller locks. Default authorization denies speech; the ordinary app has no adapter caller and still requires model setup. SDK/framework string/audio retention is unverified.

Preparation has a five-second deadline. Timeout, replacement, failure and close complete once; late results cannot publish readiness. Native exceptions map to unavailable/failed metadata without messages. SDK stop errors invalidate readiness. The engine visibility manifest query is limited to TTS services. Rate/gain/text bounds and current-turn checks apply before the native call. Actual audio-stop latency is a physical gate, not a claim from asynchronous cancellation.

Actual checks PASS: Debug Kotlin compilation/lint, eight focused tests, normal Android Debug build, same iPhone 18 Pro normal app build and three fresh ten-second launches before commit. A temporary API35 ARM64 instrumentation evaluator observed an eligible installed voice with network-required=false and real SDK synthesis completion for a fixed generic sentence; its class was removed and the normal APK restored with app data preserved. [Recorded results](../../packages/offline-speech/tests/android-results.json). Initial evaluator attempts timed out because onCreate omitted start(); the corrected entry point passed. Preparation deadlines/race checks were retained and tested. No engine-stall or physical success is inferred from that harness defect.

Reproduce focused checks using installed JAVA_HOME/ANDROID_HOME from `Eilo/apps/mobile/android`: `./gradlew :app:compileDebugKotlin :app:lintDebug :app:testDebugUnitTest --tests 'com.eilo.foundation.AndroidOfflineSpeechTest' --offline --max-workers=2`. From `Eilo`, run `python3 packages/offline-speech/check_android.py --serial emulator-5554 --android-sdk <installed-SDK> --java-home <installed-JDK17>` against the existing emulator. No tools/voices are installed and no microphone is used. [Android API reference](https://developer.android.com/reference/android/speech/tts/TextToSpeech) documents voice selection, queued speech, volume and stop; [progress callbacks](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener) are operational evidence, not proof the user heard it.

Physical airplane-mode synthesis/traffic/intelligibility, first audible audio and interruption latency are NOT RUN. The engine is a separate OS process with its own network permissions; an app-level boundary is not traffic-isolation proof. Privacy/vendor-retention and production speech-policy integration remain release gates.
