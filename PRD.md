## Product and audience
Eilo is an English, voice-first mobile companion for casual, supportive conversation. Tagline: “I am here for you”. Core conversations run on the phone after model setup and are free to use; there is no cloud per-minute inference dependency. Users can speak and hear responses without typing during normal conversation. Accessible touch controls and authentication may still require native interaction. Initial adult/Australia-first pilot is a planning assumption pending owner review, not an established launch restriction.

The app responds warmly to what the user says, asks for clarification when uncertain and offers suggestions. It does not diagnose emotions, impersonate a human, guarantee emotional understanding, or provide a medical/emergency service. Do not add autonomous agent actions, speculative personality profiling or dark patterns to promote dependence.

## MVP journeys and requirements
| ID | Requirement | Acceptance evidence |
|---|---|---|
| P01 | Onboarding explains local inference, model downloads, optional accounts and privacy. Guest continuation remains available. | Guest completes setup and starts conversation without identity service connectivity after assets are installed. |
| P02 | Microphone access is requested in context after Start. Background listening and locked spoken conversation require distinct explicit choices; background is initially off. | Denial/revocation stops capture; app exit stops capture when background consent is off. No automatic capture at installation. |
| P03 | Native wake detection recognizes speech directed to Eilo, then local VAD/ASR/controller generate an English spoken response. Wake detection is not speaker authentication. | Measure wake false activation, recognition, endpointing and full turn latency on supported physical phones; low-confidence input asks for clarification. |
| P04 | Start/Stop, interruption and truthful stopped/standby/listening/thinking/speaking/error states are accessible. Stop releases capture and invalidates pending work. | A stale callback cannot resume playback, reopen a card or store content after Stop/privacy transition. |
| P05 | End conversation releases temporary turn context and returns to wake standby when listening mode remains enabled. After 60 seconds of actual conversational idle, return to standby. | Timer starts after playback/processing and resets on relevant activity; it is separate from visual-card expiry. |
| P06 | Already-enabled background/screen-off conversation continues only within permitted OS behavior. No force-quit/reboot revival promise. | Physical OS/device/audio-route tests determine support; unmet feasibility is reported, never bypassed by JS keepalives or policy abuse. |
| P07 | Optional local history and derived memory persist under explicit consent. Onboarding requires a deliberate history/private choice; neither is preselected. Private sessions persist no conversation content. | Restart preserves consented history locally; private-mode files, logs, cache and network audits find no persisted content. |
| P08 | Memory permits authenticated review, correction, delete-one/delete-all and configurable retention. Default retention is 90 days and ceiling is 250,000,000 bytes including dependent memory/inbox/journals, excluding generic models. | Expired/deleted source facts do not reappear. Warn at proposed 80% threshold; quota handling offers cleanup or explicit private mode without silent loss/upload. |
| P09 | Local device authentication protects memory and sensitive settings independently of an optional app account. Locked conversation remains generic and cannot retrieve prior personal memory. | On lock cancel sensitive playback, close protected store and clear decrypted context. Sealed locked-write composition must pass review before release. |
| P10 | Optional email/password, Google and Apple-on-iOS account flows store minimal identities/auth data in Neon PostgreSQL. Guest/offline core remains available on outage. | Sign-in does not restore history. Switching identities requires local authenticated reset; sign-out does not silently erase local history. Account deletion and local history deletion are distinct. |
| P11 | Home has blue/light-purple centre-out rounded ripples when actively listening/speaking, native navigation, essential controls and truthful states. | Reduced Motion uses a static mark; large text/screen-reader/native contrast tests pass on declared devices. One-second motion reference is not a performance pass. |
| P12 | Selected visual categories accompany speech: text on, images/videos off are proposed defaults. Voice only suppresses cards and remembers prior choices. | Without rich information, released assistant spoken clauses appear progressively as default text. No draft reasoning or cancelled-generation text is shown. |
| P13 | Rich cards present only available allowed content, source attribution, close and Keep visible. Initially at most three results. Video is explicit-play only and pauses Eilo speech/listening; manual Resume follows. | Unsupported media is not fabricated; media/player/network caches are bounded and cleared. Choices do not themselves authorize outbound search. |
| P14 | Cards expire after 20 seconds of true visual inactivity, adjustable 10/20/60 or current-session pin. Speech/loading/video/interaction suspend/reset expiry as specified. | Screen-reader activity is respected; pin cannot bypass lock/Stop/privacy transitions. Close affects display, not capture. |
| P15 | Optional live search is off until enabled and each minimized query/provider is previewed and explicitly confirmed. Proposed query cap 256 characters. | Cancellation yields zero search request. No whole transcript, retrieved memory, emotion profile, account ID, raw audio, GPS or personal model enters the payload. No query/result storage in Neon or service logs. |
| P16 | Foreground results display inside Eilo. Android outside-app overlay is separately consented/permissioned and feasibility-gated. iOS uses generic permitted notification fallback; full content may require app opening. | Locked/system notifications contain no personal reply/query/media. No arbitrary Siri-style iOS overlay, forced launch or guaranteed notification expiry is promised. |
| P17 | All personal history remains local, encrypted and excluded from backups/transfer; sensitive data is absent from logs, notifications and app snapshots. | Native backup/restore, key lifecycle, traffic, privacy-epoch race and disk inspections supply release evidence. |

## Non-functional targets and release gates
- Measure end-of-user-turn to meaningful reply audio: median 1.5 seconds and p95 3 seconds are engineering targets, not results. Interruption stop p95 target: 300 ms. Record cold/warm conditions and the entire pipeline.
- A 60-minute foreground/screen-off endurance run must establish sustained latency, battery/RAM/thermal behavior and interruption correctness on declared support devices. No current support matrix is certified.
- Offline guest core must work with networking disabled after setup. Model/auth/search outages must not silently enable cloud inference or block core offline conversation.
- Stable opaque surfaces, measured 4.5:1 normal-text and 3:1 essential-control contrast targets; 48-logical-unit shared touch regions, text scaling, VoiceOver/TalkBack and Reduced Motion. Targets do not establish compliance by themselves.
- Privacy/security failures, unreadable lock-state policies, unreviewed model/media licensing and unresolved platform viability block affected release scope. Report not-tested distinctly from passed.

## Explicitly outside MVP
Calls, camera control, arbitrary app automation, location permission/history, ambient continuous transcription, advertising/tracking SDKs, cloud history sync, cloud conversation inference, embeddings by default, on-device personal training and cloud model aggregation. These were discussed as future possibilities, not approved implementation work. A future change needs its own consent, feasibility and privacy review.

## Assumptions and traceability
Design defaults, device baselines (Android15+/iOS18+/8 GB), pilot territory/cohort and budget/timeline remain the management-plan assumptions. Do not make them production promises. The baseline JSON v1.5 holds 175 stable task IDs and dependencies; the CSV holds execution tracking. Preserve IDs and connect each implemented task to its requirement and evidence. New coding conventions are in ARCHITECTURE.md and are documented choices, not retrospectively approved dependency versions.
